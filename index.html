Built for workflows, not one-off prompts.

RunHelm treats agents as workflow nodes. The same execution model applies to agent tasks, function tasks, and API-call tasks, so each step can be scheduled, inspected, retried, and wired to downstream work.

Workflow orchestration

Define tasks, dependencies, data bindings, and optional schemas so each run has a deterministic control plane.

Isolated workers

Workers claim queued tasks and execute agent, function, or API payloads behind a replaceable executor boundary.

Observable runs

Run state tracks pending, running, input-needed, completed, and failed tasks so operators can understand what happened.

Resumable model

The orchestrator persists progress events and state transitions so workflows can pause, resume, and continue after feedback.

Start locally with Docker.

The local install path uses a small wrapper and Docker Compose so users can run RunHelm without installing Rust or Node.js.

curl -fsSL https://raw.githubusercontent.com/markosski/runhelm/main/packaging/install.sh | sh
runhelm init
runhelm up

What starts

The generated local environment starts the orchestrator, worker, and frontend services and stores local configuration under~/.runhelm.
